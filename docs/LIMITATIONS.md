# 제한 사항과 보안 경계

## 자동 제출의 처리 방식

학생이 `응답 제출하기`를 누르면 브라우저가 전체 응답 JSON을 일회용 AES-256-GCM 키로 암호화하고, 그 키를 관리자 RSA 공개키로 다시 암호화합니다. Cloudflare Worker는 Turnstile을 검증한 뒤 암호문만 `data` 브랜치에 저장하고 같은 파일을 재조회해 저장 내용을 확인합니다.

- Worker와 GitHub에는 평문 답변이나 관리자 복호화 개인키가 전달되지 않습니다.
- 공개되는 메타데이터는 설문 ID, 리비전, 무작위 응답 ID, 제출 시각, 암호화 방식입니다.
- 저장소 방문자는 암호문과 위 메타데이터를 볼 수 있습니다.
- Cloudflare와 GitHub는 서비스 동작에 필요한 접속·요청 메타데이터를 처리할 수 있습니다.

관리자는 결과 화면에서 개인키 PEM을 선택합니다. 암호문 조회와 복호화는 브라우저에서 이뤄지고, 개인키는 메모리에만 유지됩니다.

## 복구와 키 교체

개인키를 잃으면 기존 응답은 복구할 수 없습니다. `.response-keys/private.pem`을 암호화된 오프라인 저장소 등 별도 안전한 위치에 백업해야 합니다. 설문 수집 도중 키를 교체하면 이전 키와 새 키가 각각 필요하므로, 수집 종료 전에는 공개키를 임의로 바꾸지 않습니다.

## 수동 백업

Worker, Turnstile 또는 GitHub 장애가 있을 때 학생은 동일한 평문 응답 JSON을 내려받아 강사가 안내한 안전한 전달 경로를 사용할 수 있습니다. 파일 다운로드만으로는 자동 제출되지 않습니다. 평문 응답 파일을 공개 저장소에 업로드하지 않습니다.

## 공개 저장소와 개인정보

`data` 브랜치도 공개됩니다. 실제 응답 파일은 반드시 암호문이어야 하며, 이름·연락처·이메일·정확한 생년월일 같은 직접 식별정보를 문항으로 추가하지 않는 것이 원칙입니다. Git 이력은 파일 삭제만으로 완전히 지워지지 않습니다.

응답 파일명과 공개 메타데이터까지 숨겨야 하는 조직이라면 공개 GitHub 저장소를 저장 계층으로 사용하는 이 설계가 맞지 않습니다. 비공개 저장소 또는 승인된 전용 수집 시스템이 필요합니다.

## GitHub API 구조의 규모 제한

응답 하나당 `data` 브랜치에 커밋 하나가 생성됩니다. 동시에 제출되면 Worker가 브랜치 충돌을 최대 3회 재시도합니다. 현재 관리자 동기화는 설문당 1,000개 미만의 응답을 대상으로 합니다. 그 이상은 Git Trees API 기반 페이지 분할 또는 별도 승인 저장 계층이 필요합니다.

## 관리자 설문 저장

설문 편집 화면의 fine-grained PAT는 React 메모리에만 있고 저장되지 않습니다. `hiphop5782/smart-survey` 저장소의 `Contents: Read and write` 최소 권한만 부여하고 신뢰할 수 있는 관리자 기기에서 사용해야 합니다. 정적 브라우저 앱의 런타임 토큰은 손상된 브라우저 확장 프로그램까지 방어하지 못합니다.

## 코드 퀴즈 정답

공개 설문 JSON에는 정답을 넣지 않습니다. 강사가 결과 화면에서 선택한 정답 키도 현재 브라우저 메모리에만 유지됩니다.
